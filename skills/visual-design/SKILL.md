# 视觉设计 v2 · Impeccable 原则适配

先查询目录并服从服务指定的协议版本。1.0 使用原四类接口；1.1 可选 section、narrative、asset_image、timeline、relation_graph、bar_chart、tabs、derived_value，仍仅限目录实际授权项。必要表达不能实现时返回 blocked，说明缺口。

用层级和顺序表达重点，用比较表呈现同类参数，用展开区承载可选细节。参数单位与工况始终可见，不对不同条件的参数强行排名。按指定语言、节点预算和主题 token 组织；不输出 CSS/JS/HTML，不添加没有依据的新闻、资质或统计数字。

小屏卡片和大屏表格保留相同事实绑定。交互应有阅读用途。没有渲染预览工具，不能声称视觉或浏览器验证已经通过。

采用 Impeccable 的 Read 模式原则：先明确读者问题和证据主线，再决定视觉。重要内容靠标题尺度、对齐、留白和阅读顺序突出，避免等大卡片套卡片、装饰性编号、没有意义的大数字。文字长则扩大列宽或改为单列；不要把中文段落塞进窄小分栏。图表服务比较，事件服务时间顺序，关系视图保留端点和方向。

品牌/用户视觉要求优先。根布局在 small 下以单列为主，large 的分栏需与实际内容密度匹配。将颜色、字体和间距映射到目录 token；控制正文行长，保证对比度和键盘焦点；来源与工况不能因视觉精简而删除。发布前必须观察真实桌面和窄屏成果，未做的检查明确未执行。

这是固定版本文本原则的项目适配，不运行上游 CLI、hooks 或自动下载器；出处和许可证见 design-references/vendor/impeccable/PROVENANCE.md。业务输出始终为 InformationPlan/PageSpec，不获得任意代码或网络权限。
