# 第一个设计练习：让采购人员比较三个产品

> 2026-10-11：用户已明确不采用此练习。仅保留历史文件，不再作为当前设计 Agent 开发依据；最新方向见 ../../development/design-agent-onboarding.md。

这是人工编写的合成输入与参考设计，帮助我们一起确定设计 Agent 的任务。**不是 Agent 生成结果，不是通过审查的页面，也不是可执行的 InformationPlan/PageSpec。** 所列组件和交互均为拟实现能力。

先读本页即可理解设计；原始资料见 [source.md](source.md)。这份参考设计不是唯一正确答案，未来模型可以采用其他有依据的组织方式。

## 给设计 Agent 的任务

受众：需要做初步设备比较的采购人员。

目标：帮助读者了解 CY-T1、CY-C2、CY-G3 的监测内容与部署差异，识别进一步采购前还缺哪些信息。

用户要求：优先展示产品差异；保留简短企业介绍和发展事件；事实能回查来源。不要编造价格、精度、认证、客户或采购推荐，不把较新的型号称为更高级。

本练习的资料范围仅为 source.md v1。设计过程不能访问其他企业信息，也不能把现实世界常识补充成该企业事实。

## 页面应该先让读者看到什么

拟定页面标题：**澄野环境监测｜三款设备对比**。

首屏说明：比较监测内容、供电与数据读取方式，了解下一步需要确认的采购信息。页面顶部保留“合成演示资料”标识。

| 顺序 | 模块 | 读者的问题 | 设计原因 |
| --- | --- | --- | --- |
| 1 | 三款设备对比 | 三款有什么差别？ | 采购任务优先，直接横向对齐相同属性 |
| 2 | 采购前还需确认 | 现在能否做最终选择？ | 让缺少精度、价格等信息的限制紧邻比较结果 |
| 3 | 企业与产品历程 | 这家企业做什么，产品何时推出？ | 提供背景；不让企业故事挤占比较空间 |

这里的三个模块是根据本案例作出的选择，不是以后所有企业必须套用的栏目。

## 第一模块：三款设备对比

| 比较项 | CY-T1 | CY-C2 | CY-G3 |
| --- | --- | --- | --- |
| 监测内容 | 温度、相对湿度 [P03] | 温度、相对湿度、二氧化碳 [P04] | 温度、相对湿度、二氧化碳 [P05] |
| 供电 | USB [P03] | USB [P04] | PoE [P05] |
| 联网 | 不支持 Wi-Fi；USB 导出本地记录 [P03] | Wi-Fi [P04] | 以太网 [P05] |
| 记录导出 | USB 本地导出 [P03] | 平台导出 [P04] | 平台导出 [P05] |
| 厂家列出的场景 | 档案室本地温湿度记录 [P03] | 教室联网环境监测 [P04] | 办公楼有线部署 [P05] |
| 采样间隔 | 60 秒 [P02] | 60 秒 [P02] | 60 秒 [P02] |

表旁说明：均为标准配置；采样间隔不代表响应时间；应用场景是资料描述，尚不是适用性认证。[P02、P07]

为什么用比较表：读者要比较同一组属性；为每个产品各写一大段文字，会让读者反复寻找对应参数。此处不用雷达图或“综合评分”，因为没有评分标准，也没有可支持优劣排名的数据。

拟实现交互：

- “只看差异”开关：隐藏三列完全相同的采样间隔行，其余行保留；切换后显示“已隐藏 1 项相同信息”，允许恢复。
- 点击具体单元格的来源标记：显示 source.md v1 的对应段落和原文。开关切换、横向滚动后来源映射不变。
- 手机端：属性列保持可识别，产品列可横向滚动并提示还有内容；不能缩小到难以阅读或直接丢弃第三个型号。

上述行为是后续开发的验收要求，本 Markdown 不实现这些按钮。

## 第二模块：采购前还需确认

明确显示：“当前资料不足以完成最终采购选型。”依据是 P07 中缺少关键采购及技术信息，不代表产品不合格。

| 待确认信息 | 当前展示 |
| --- | --- |
| 测量精度、量程 | 未提供；不能由型号或联网方式推断 [P02、P07] |
| 认证 | 未提供 [P02、P07] |
| 价格、库存、交付周期 | 未提供 [P07] |
| 质保期限 | 未提供 [P07] |

不显示购买按钮或虚构联系方式。没有价格就不能标“免费”，没有认证不能标“未通过认证”。

## 第三模块：企业与产品历程

企业简介：澄野环境监测成立于 2018 年，提供室内温湿度记录和二氧化碳监测设备。[P01]

时间表达：2018 成立 → 2021 推出 CY-T1 → 2023 推出 CY-C2 → 2025 推出 CY-G3。[P06]

选择时间轴是因为这里是有日期的事件序列。每个事件保留来源；手机端可纵向排列。不把推出新产品解释为营收增长或行业领先。

## 怎样把这份设计转成两层产物

| 人能读懂的决定 | 将来由谁记录 |
| --- | --- |
| 受众是采购人员；比较优先，背景后置 | InformationPlan |
| 哪些信息展示，哪些缺失，为什么这样分组 | InformationPlan |
| 本案例没有排名依据，不做评分排行榜 | InformationPlan 中的设计理由/约束 |
| 比较表、差异开关、时间轴、窄屏安排 | PageSpec |
| 每个数据和事件指向哪个事实及来源 | PageSpec 的数据绑定及共享事实协议 |

目前 P01—P07 是文档段落定位。实现时先映射为现有事实协议中的真实 ID；这里不另外发明一套候选快照格式，也不把段落编号冒充 claimId。

## 改变目标后，页面应怎样变化

同样资料，如果用户改为“向公众介绍企业及产品发展”，合理方案可以把企业简介和历程前置，产品能力概览随后，完整参数比较作为展开内容。原始数值、场景描述与缺失状态不变。

这用于检查 Agent 是否理解目标，而不是总是返回同一模板。它不要求模型每次必须选择本页的相同布局。

## 之后怎样判断 Agent 做得好不好

| 检查项 | 可接受 | 不可接受 |
| --- | --- | --- |
| 内容准确 | CY-G3 显示 PoE/以太网 | 自行改成 USB/Wi-Fi |
| 数据含义 | 60 秒标为采样间隔 | 60 秒标为响应时间 |
| 设计重点 | 产品差异容易找到 | 大段公司故事压住参数 |
| 缺失处理 | 精度、价格标为未提供 | 填 0 或猜一个数值 |
| 比较逻辑 | 明确不同配置 | 把 G3 标为最高性能或性价比最高 |
| 证据 | 可回查确切段落与版本 | 只在页脚写“来源：企业资料” |
| 能力边界 | 没有可用比较组件时提出能力缺口 | 把占位组件当成可用并宣布成功 |

第一版先看事实是否忠实、比较是否清楚、缺失是否诚实。视觉配色可以随后调整。
