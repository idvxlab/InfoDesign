## 实际实现

- `config/env.ts` 显式验证提供方、模型、HTTPS 端点及 API key。`readModelConfigFromModels` 只读取显式选定模型的端点和已支持的 `compat.maxTokensField`，模型级优先于提供方级；也可用 `APP_MODEL_MAX_TOKENS_FIELD` 显式配置，不从模型名称猜测。只支持本轮核对的 `openai-completions`；拒绝端点中的凭据、查询参数和片段，不自动加载 `.env`。仅测试调用方可显式允许回环 HTTP。
- `session-factory.ts` 使用锁定的 Pi SDK 0.99.1 创建真实会话：`ModelRuntime.create`、`setRuntimeApiKey`、`SessionManager.inMemory`、`SettingsManager.inMemory` 与 `createAgentSession`。接口已按容器中该版本的文档、类型和实现核对。
- 每个任务拥有独立临时目录和历史。API key 只作运行时覆盖，不作为配置命令执行，不写入 auth 文件。关闭模型目录联网刷新、扩展、Skills、上下文文件、个人历史、后台预热、遥测、自动压缩和自动重试。
- 会话只注册 `read_document`；不提供内置 bash、任意文件读写或开发工具。资料及 scope 由可信调用方提供，随后复制为快照；调用方不能在后续操作中修改该快照。工具请求只接受资料 ID、确切版本 ID 和块 ID。程序检查操作权限、项目、资料版本、块及 paragraph 定位。
- 新增权威 `runtime/read-document-request`、`runtime/read-document-result` Schema 和生成类型；注册表支持已注册 `$id` 的定义片段以复用 scope 规则。工具返回原文、资料版本、内容指纹和位置；仍不支持未完成的文档定位类型。
- `read-probe.ts` 要求提供工具实际执行成功的回执；最终输出必须为严格 JSON，既须通过 Schema，也须与指定资料块的本次回执一致。只输出正确 JSON、伪造原文或越权读取都不能通过。
- 模型调用通过 SDK `session.agent.streamFunction` 包装，执行前限制次数和上下文；工具执行前扣除工具次数。超时、预取消和在途取消会传播到模型请求，并释放会话、临时目录、监听器和定时器。
- `transport-diagnostics.ts` 记录 fetch 尝试计数、HTTP 状态及固定网络错误码；不读取响应正文或保存 URL、头部、原始异常。fetch 尝试不证明网关已收到或计费。
- 诊断事件只保留白名单字段，错误用稳定原因码，不回显原始网关异常、提示、工具参数或秘密。`usage` 仅合计供应商已报告的有效值；另记录有／无用量响应数，避免把部分小计视为完整用量。缺失用量为 `null`，实际金额 `billedAmount` 始终为 `null`。

固定系统提示仅用于本轮受控读取任务，专业 Skills 留待 B3/B4 显式接入。临时工作区与会话隔离不等于安全沙箱，实际 SDK 执行全部位于受限容器。

## 可执行限制

| 限制 | 单次任务上限 |
| --- | --- |
| 时间 | 90 秒 |
| 模型调用 | 3 次；禁用自动重试 |
| 工具执行 | 2 次，只读授权资料块 |
| 输出参数 | 每次请求 `maxTokens: 1024` |
| 模型上下文 | 每次序列化后最多 12,000 字节 |

程序配置可以降低这些上限，不能提高。上下文字节限制不是供应商计费 token 上限；外部平台是否严格遵守输出参数须真实验收。SDK 模型描述中的 16,384 上下文为本任务的保守配置，内部成本 0 为 SDK 必需的占位值，均不代表已确认的模型能力或免费价格。视觉能力未验证。

## 真实验收入口与范围

`pnpm eval:b2` 默认退出 2 且不调用模型。必须同时显式传入 `--live` 和 `APP_RUN_LIVE_EVAL=1`；凭据和调用范围应先获得授权。

必需配置：`APP_MODEL_PROVIDER`、`APP_MODEL_ID`、`APP_MODEL_API_KEY`，以及 `APP_MODEL_BASE_URL`（或显式 `--models-file /path/to/models.json` 提供选定模型的端点）。模型列表只用于核对明确选定的提供方／模型和端点，不读取或执行其中的 apiKey 配置。`APP_MODEL_API` 可指定 `openai-completions`。

容器内入口示例（环境变量由启动容器时注入，不能把真实密钥写入命令或仓库）：

```bash
pnpm eval:b2 --live --models-file /run/config/models.json
```

使用现有内部网络和出口代理即可，无需停止 Pi 终端或扩大白名单。可从 B2 候选镜像启动一次性容器，用户 1000、只读系统、无 capabilities、仅 `/tmp` 可写，单独只读挂载模型配置；不挂载开发 Pi 主目录或企业资料。`APP_B2_REPORT_PATH` 可选，报告以 0600 新建且禁止覆盖；未指定时输出安全 JSON 报告。

仓库默认 CLI 的测试数据仅来自合成夹具 `synthetic/evidence-input.json`；固定任务要求读取 `doc_profile/docv_profile_1/b004`。工具只可读取该夹具 scope 授权的段落，最多两次；发送内容还包括固定任务指令、工具 Schema 和本次上下文。不加载企业真实资料或历史会话。验收应观察模型发出工具调用、本地工具执行、输出通过 Schema 和回执一致性检查，并记录接口用量及清理结果。
