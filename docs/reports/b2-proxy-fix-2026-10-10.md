# B2 环境代理修复与离线验证

日期：2026-10-10。**应用层修复与离线验证已完成；未调用真实模型，B2 仍需真实工具验收。**

## 根因证据

上一轮重验记录为 `EAI_AGAIN`，未收到 HTTP 响应。随后在无网络、无凭据的容器内，记录了导入 Pi 运行层前后的全局调度器类型与覆盖调用栈：

| 时点 | `undici.globalDispatcher.1` | `undici.globalDispatcher.2` |
| --- | --- | --- |
| Node 24.11.1 启用既有环境代理后 | `EnvHttpProxyAgent` | 未设置 |
| 导入 Pi SDK 0.99.1 后 | `Dispatcher1Wrapper` | `Agent` |

Pi 的 `SettingsManager` 导入 `core/http-dispatcher.js`，后者导入锁定的 Undici 8.10.2。其 `lib/global.js:14–15` 在新版调度器不存在时执行 `setGlobalDispatcher(new Agent())`；该函数同时写入新版和旧版全局槽，覆盖了 Node 启动时设置的环境代理。SDK 中提供代理初始化的 CLI 路径并不等于业务 SDK 导入时已完成同样的初始化。

覆盖调用栈直接指向 Undici 的 `lib/global.js`。此前本地对照也已证明：普通 Node 请求经过模拟代理，导入运行层后原生全局 fetch 不再进入代理。这说明故障来自应用所依赖的全局传输初始化；并非 Node 不支持代理，也无需调整系统 DNS、VPN 或出口限制。旧真实报告未保存失败主机名，不能将该离线结论改写为已经查到旧请求的完整网络轨迹。

## 最小修复

- 新增 `model-transport.ts`：为每个业务会话创建独立 `EnvHttpProxyAgent`，显式交给同版本 Undici fetch。只读取运行时已有的 HTTP(S) 代理和 NO_PROXY 变量，不修改进程环境或安装新的全局 fetch／dispatcher。
- `session-factory.ts` 将服务层持有的传输交给 SDK，再套用现有安全诊断；正常结束和初始化失败均释放该会话的连接池。
- 保留环境变量大小写优先级、明确的 NO_PROXY 例外、TLS 验证、预算信号、取消和 `maxRetries: 0`。代理拒绝不回退为直连。
- 将已有锁定依赖 Undici 8.10.2 声明为后端直接依赖。锁文件只新增对应 importer 的三行；没有升级包版本或改动原依赖解析图。
- 该适配器服务于当前 B2 的 OpenAI JSON/SSE 路径，接受 URL 与文本请求体；跨 Undici 实现的 Request 对象和非文本请求体明确拒绝。请求头转为标准键值对，响应仅在 Pi／DOM 类型边界做类型适配，不改写正文或诊断内容。

SDK 导入仍可能影响进程里的原生全局 fetch；本次修复使业务模型请求明确使用受控传输，未尝试重置整个进程的第三方全局状态。今后新增模型传输应复用该入口并增加对应协议测试。

## 新增回归

`tests/integration/pi-proxy.test.ts` 的 8 项测试使用真实 SDK、本地 HTTPS 模拟网关和 CONNECT 代理：

1. SDK 导入前的 Node fetch 与导入后的独立传输均经过已有代理；创建传输不改变全局调度器或环境。
2. 模型完成两次响应和一次受控读取；`max_tokens: 1024`、认证头和最终读取依据正确，未发送 `max_completion_tokens`。
3. 验证 HTTPS 代理选择、大小写优先级及显式 NO_PROXY 的本地例外。
4. 代理返回 403／407／502 时，目标即使可直接到达也不回退，不额外请求。
5. 网关 401／429／500 和 POST 连接中断不产生隐藏重试。
6. 外部取消停止在途 HTTPS 响应并清理资源。
7. 预算超时终止停滞 CONNECT，不触达网关、不重试。
8. 不受信任的 HTTPS 证书仍被拒绝。

测试在临时目录生成本地证书，仅测试子进程信任该临时 CA；没有关闭证书验证或修改系统信任。新测试子进程使用独立 TMPDIR，避免并行测试互相把对方的工作目录误判为资源泄漏。首次全量运行出现的两项目录断言冲突已据此修复，断言保留。
